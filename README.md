# MemGuard · Windows 内存 / 显存锚点管家

一个**以安全为第一约束**的 Windows 桌面工具：解决 AI 软件用完、或打开大量文件之后，内存/显存「占用下不来」的问题。支持**自动释放**与**手动释放**，并提供**内存锚点**（自动/手动记录），以锚点状态为参照决定释放多少，达标即停，避免过度释放。

> **一句话边界**：Windows 没有「一键归还内存/显存」的通用 API。本程序不伪造效果——能安全做的只有裁剪进程工作集、清理备用列表/文件缓存；真正释放提交内存或显存，只能由持有它的进程退出，因此那一步**永远需要你逐项确认**。

## 功能

| 能力 | 说明 |
|---|---|
| 实时监控 | 物理内存、可用/已用、提交内存与上限、页面文件、系统缓存、PDH 备用列表、每进程工作集与显存占用、前台窗口、CPU/磁盘忙闲、用户空闲时长 |
| 内存锚点 | 首次启动自动建立「启动基线」；系统空闲且健康时自动刷新；也可随时手动命名设置。支持切换、重命名、删除、导出。重启/过期/内存总量变化时自动判失效并暂停自动释放 |
| 锚点决策 | `目标已用 = 锚点已用 + 容差`；仅当当前超出目标才组织动作，**每执行一项就复测，达标立即停止** |
| 自动释放 | 定时巡检（默认 60 秒），**硬编码止于 L1**，任何配置都无法让自动流程结束进程 |
| 手动释放 | L1 工作集裁剪 / L2 清理备用列表与文件缓存 / L3 优雅关闭显存占用进程，逐级提供更强的效果与更明确的确认 |
| 干运行预览 | 执行前展示将影响的每个进程、预计释放量、跳过项及原因、副作用说明；确认的是这份计划，执行的就是这份计划 |
| 审计日志 | 记录每次动作、跳过原因、前后数值、Win32 错误码，可导出、可清理（默认保留 30 天） |
| 呈现 | 中文 tkinter 面板（概览 / 锚点 / 释放 / 保护名单 / 设置 / 日志 / 使用说明）、可选系统托盘、气泡通知 |

### 分级动作与副作用

| 级别 | 动作 | 权限 | 能否自动 | 副作用 |
|---|---|---|---|---|
| L0 | 只读采集与预览 | 标准 | — | 无 |
| L1 | `EmptyWorkingSet` 裁剪进程工作集 | 标准 | ✅ 自动上限 | 物理页换出到页面文件，切回应用可能短暂卡顿；进程不退出 |
| L2 | 清备用列表 / 系统文件缓存 | **管理员** | ❌ | 短时间内磁盘 IO 可能上升 |
| L3 | 向占用显存的进程发 `WM_CLOSE`，超时后**再次确认**才强制结束 | 标准 | ❌ | 未保存的改动可能丢失 |

`nvidia-smi --gpu-reset` 之类的 GPU 重置会中断所有 GPU 任务，**未被纳入任何流程**。

## 快速开始

**方式 A：直接运行（推荐给使用者）**
从 [Releases](../../releases) 下载 `MemGuard.exe`，双击即可。单文件、无需 Python。L2 需要右键「以管理员身份运行」，普通权限下其余功能全部可用。

**方式 B：源码运行**
```bat
git clone https://github.com/jaja1620/MemGuard.git
cd MemGuard
run.bat
```
要求 Windows + Python 3.10+ 且带 `tkinter`。核心功能**零第三方依赖**（仅标准库 `ctypes` / `tkinter`）；系统托盘为可选增强：
```bat
pip install -r requirements.txt
```
找不到 `tkinter` 时，入口会自动寻找系统里其它带 tkinter 的 Python，全部找不到则降级为无界面 CLI 模式。

**方式 C：自行打包 exe**
```bat
build.bat
```
产物在 `dist\MemGuard.exe`。

## 安全设计

避免「错误释放」的九道闸门：

1. 自动流程硬编码止于 L1；配置里的 `auto_max_level` 恒为 1，非法值一律收敛。
2. 硬保护名单（系统关键进程、杀软、外壳进程、程序自身）+ 用户保护名单，界面不可移除硬名单。
3. 有可见主窗口的进程默认不参与自动裁剪/结束。
4. L3 默认全不勾选 → 先发 `WM_CLOSE` 等待保存 → 超时后另弹一次确认才允许强制结束。
5. 干运行预览；UI 执行时绑定**已确认的那份计划**（3 分钟有效期 + 计划指纹），不重新生成。
6. 执行前用新快照复核进程身份，PID 复用 / 进程已退出 / 新受保护一律剔除并写明原因。
7. 前置检查：页面文件余量、开机时长、CPU/磁盘忙闲、用户空闲、前台交互、冷却时间、权限状态；不通过即跳过并记原因。
8. 单实例、全局「暂停自动释放」、配置零校验（非法值收敛到合法区间并回显真实生效值）、全量审计日志。
9. 不改页面文件、不重启系统、不动注册表关键项、不联网；数据只写 `%LOCALAPPDATA%\MemGuard`。

采集侧同样保守：任一底层 API 失败只降级为「无法读取」，绝不臆造 0；异常被逐项兜底，不会拖垮主程序。

## 已知限制

- **显存没有回收 API**：只能由占用进程释放，因此显存处置是「列出 → 你勾选 → 优雅关闭 → 二次确认」。
- 无 NVIDIA 显卡工具时，改用 PDH 按进程聚合显存已用值；专用显存**总量如实标注「未知」**，不显示虚假百分比。
- L2 需要管理员权限；当前版本要求整个常驻程序以管理员运行，权限暴露面偏大（改进见路线图）。
- 自动释放需同时满足「可用内存低于阈值」与「超出锚点」，在内存充裕的机器上**可能长期不动作**——这是刻意的保守设计，主动清理请用手动释放或勾选「不受锚点限制」。
- 仅支持 Windows；深色主题、日志筛选、锚点导入等尚未实现。
